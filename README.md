# 사방팔방 AICC · 소규모 사업장을 위한 AI 상담

사방팔방 4인 팀이 캡스톤디자인에서 개발한 텍스트 상담 시스템입니다. 병원·식당·온라인 상점의 고객이 예약, 주문, 배송, 매장 정책을 채팅으로 문의하면 시스템이 질문에 맞춰 정보를 조회하거나 상담사에게 넘깁니다.

이 저장소는 팀 백엔드의 개인 포크입니다. 저는 **상담 평가 문항과 판정 기준 설계**를 맡았고, 오픈소스 LLM을 로컬에서 실행할 수 있도록 vLLM 연동 환경을 구성했습니다. [팀 백엔드](https://github.com/SabangSquad/aicc-back) · [프론트엔드](https://github.com/SabangSquad/aicc-web) · [인프라](https://github.com/SabangSquad/aicc-infra)

## 같은 환불 문의에도 필요한 답은 다르다

| 평가 문항 예시 | 기대 동작 | 확인할 기준 |
| --- | --- | --- |
| “환불 규정 어떻게 되나요?” | 매장 매뉴얼을 찾아 환불 기간과 조건을 안내합니다. | 정책에 근거해 답했는가? |
| “환불 처리해주세요” | 실제 처리 요청으로 분류하고 상담사 연결을 안내합니다. | 고객의 의도를 파악하고 상담사에게 적절히 넘겼는가? |

두 질문은 같은 카테고리에 속하지만, 하나는 정책을 설명해야 하고 다른 하나는 후속 조치가 필요합니다. 문항을 설계할 때는 같은 주제 안에서도 질문의 표현과 앞선 대화에 따라 기대 동작이 달라지는 경우를 넣었습니다. [문항집의 환불 사례](description_md/chat_test_case.md#L692-L699) · [Supervisor 분류 프롬프트](src/prompts/templates.js#L59-L112)

## 평가 문항과 판정 기준

병원 6개, 식당 7개, 이커머스 7개로 상담 주제를 나눴습니다. 각 주제에 단순 질문, 애매한 질문, 정책 질문, 조건이 붙은 질문, 행동 요청, 불만, 로그인 필요, 정보 부족, 이전 대화 참조, 복합 요청의 10가지 유형을 적용했습니다. 업종과 질문 유형을 먼저 정의하고, 생성형 AI를 활용해 질문 표현을 구체화했습니다. [업종별 평가 문항집](description_md/chat_test_case.md)

수동 기능 점검에서는 기대한 동작이 수행됐는지 확인했습니다. 응답 품질은 다음 여섯 기준을 두고 LLM이 항목별로 채점하는 방식(LLM-as-a-judge)을 시도했습니다.

| 판정 기준 | 확인하는 내용 |
| --- | --- |
| 의도 분류 | 정책 문의, 정보 조회, 실제 처리 요청을 구분했는가? |
| 로그인 유도 | 개인 주문·예약 정보에 접근해야 할 때 로그인을 안내했는가? |
| 정책·기본 정보 | 매장 정책과 운영 정보에 근거해 답했는가? |
| 대화 맥락 | “그거”, “그럼”이 앞선 대화에서 무엇을 가리키는지 파악했는가? |
| 상담사 전환 | 사람이 직접 처리할 요청을 적절히 넘겼는가? |
| 가드레일 | 상담 범위를 벗어나거나 부적절한 요청을 처리 기준에 맞게 다뤘는가? |

공개 문항집에는 챗봇 응답과 작성 과정에서 보완한 예시 답변이 함께 담겨 있습니다. 문항과 판정 기준은 평가 설계를 보여줍니다. 성능을 다시 측정하려면 문항과 기준을 먼저 고정하고, 챗봇 원본 출력과 건별 판정을 함께 남겨야 합니다.
